# 前端样式改良设计方案（简版）

> 版本：2026-09-09 v1
> 目标：**去灰提清晰 + 图谱按大文件夹分色**，最小改动（核心只动 2 个文件 + 2 处配置），不做大规模重构。

---

## 1. 目标与原则

| 原则 | 说明 |
|:---|:---|
| 最小改动 | 核心改动集中在 `ocean.ts`（色值）与 `graph3.inline.ts`（取色函数），不动 19 个组件 scss、不引入发光/渐变/动画 |
| 去灰提清晰 | 解决「整体灰蒙蒙、看不清」：背景纯白、中间色加深、节点不透明度提高 |
| 简单分色 | 放弃复杂的节点语义四色体系，**按大文件夹（一级目录 / 大区）分色**，一个取色函数搞定 |
| 兼容按域覆盖 | 颜色仍在 quartz.config 体系内，`settings/<domain>/quartz.config.json` 天然支持按业务域覆盖 |

---

## 2. 现状问题诊断

| # | 问题 | 代码根源 |

| 1 | 页面灰蒙蒙 | 浅色模式背景 `#f8fafc` 微蓝灰 + 中间色 `--gray #94a3b8` 明度过高（节点/次要文字都发灰） |

| 5 | 中文难看 | 字体全是拉丁字体（Schibsted Grotesk / Source Sans Pro），中文回落系统宋体 |

## 5. 改动二：图谱按大文件夹分色

### 5.1 调色板（8 色，品牌蓝为固定首色）

以品牌 hue（202°）为首色，色轮均分，饱和度 60-70%。

| # | 浅色模式 | 暗色模式 | |
|:---|:---|:---|:---|
| 1 | `#0369a1` 品牌蓝 | `#38bdf8` | 固定首色 |
| 2 | `#0d9488` 青 | `#2dd4bf` | |
| 3 | `#7c3aed` 紫 | `#a78bfa` | |
| 4 | `#ea580c` 橙 | `#fb923c` | |
| 5 | `#16a34a` 绿 | `#4ade80` | |
| 6 | `#db2777` 玫红 | `#f472b6` | |
| 7 | `#ca8a04` 金 | `#facc15` | |
| 8 | `#4f46e5` 靛 | `#818cf8` | |

### 5.2 取色规则（简单版，共 4 条）

1. **tag 节点** → `--tertiary`（保留现状）
2. **当前浏览页** → `--secondary`（保留现状，描边高亮）
3. **核心节点 / 大区内节点** → 所属大区的颜色（`coreToRegionMap` 已存在，直接继承 → 展开大区后，区内节点与大区同色，归属感一眼可见）
4. **大区节点本身** → 按 `regionNodeInfoMap` 顺序依次取调色板（首区 = 品牌蓝）
5. **散点/跨区节点**（不在任何大区内）→ 按一级目录名分配调色板

### 5.3 实施伪代码（graph3.inline.ts）

```ts
// ===== 顶部新增（约 20 行）=====
const PALETTE_LIGHT = ["#0369a1", "#0d9488", "#7c3aed", "#ea580c",
                       "#16a34a", "#db2777", "#ca8a04", "#4f46e5"]
const PALETTE_DARK  = ["#38bdf8", "#2dd4bf", "#a78bfa", "#fb923c",
                       "#4ade80", "#f472b6", "#facc15", "#818cf8"]
const palette = document.documentElement.getAttribute("saved-theme") === "dark"
  ? PALETTE_DARK : PALETTE_LIGHT

// 大区 → 颜色（按 regionNodeInfoMap 插入顺序；用索引分配，与 groupKey 内容无关，
// 规避已知的 groupKey 尾部空格脏数据问题）
const regionColorMap = new Map<SimpleSlug, string>()
let _i = 0
for (const id of regionNodeInfoMap.keys()) {
  regionColorMap.set(id, palette[_i++ % palette.length])
}

// 一级目录 → 颜色（散点兜底）
const folderColorMap = new Map<string, string>()
function folderColor(id: string): string {
  const seg = id.split("/")[0]
  if (!folderColorMap.has(seg)) folderColorMap.set(seg, palette[folderColorMap.size % palette.length])
  return folderColorMap.get(seg)!
}

// ===== 替换 color(n)（原 1498-1503）=====
const color = (d: NodeData) => {
  if (d.id === slug) return computedStyleMap["--secondary"]          // 当前页，保留
  if (d.id.startsWith("tags/")) return computedStyleMap["--tertiary"] // 标签，保留
  const rid = coreToRegionMap.get(d.id)
  if (rid) return regionColorMap.get(rid) ?? folderColor(d.id)      // 核心继承大区色
  if (d.isRegion) return regionColorMap.get(d.id) ?? computedStyleMap["--secondary"]
  return folderColor(d.id)                                          // 散点按一级目录
}
```

### 5.4 节点 / 连线绘制参数（3 处小改）

| 位置（graph3.inline.ts） | 现状 | 改为 |
|:---|:---|:---|
| 大区节点 1789-1790 | `--secondary` 填充 18% + 虚线描边 | `regionColorMap.get(nodeId)` 填充 12% + 同色 2px 描边 |
| 核心节点 1798 | `--secondary` 填充 55% | 大区色（或 folderColor）填充 **85%** |
| 叶子节点 1801 | `color(n)` | 不动，自动走新 color() |
| 连线颜色 1541-1544 / 1979-1982 | `--lightgray` / 聚合边 `--tertiary` | source 端为核心/大区时用其区色（alpha 0.4），否则保持 `--lightgray` |

> 连线跟随节点着色后，图谱从「一片灰线」变成「按区着色的关系网」，是去灰观感提升最大的一项。

### 5.5 已知限制（可接受）

- 切换浅/深主题后，图谱色板不自动刷新（Pixi 已渲染），需重新打开页面/图谱。后续可监听主题切换事件重算，本次不做。
