# 附件处理说明

本文件说明 **v5 里附件（资源文件）链接的处理规则**：frontmatter 与正文两条渲染路径上，"什么算附件、会挂什么属性、怎么拿到想要的另存文件名"。

> 落地版本：v5，2026-09-21。改动全部在**本地 fork 插件**里（`plugins-local/note-properties-pro`、`plugins-local/crawl-links-pro`），v5 核心与服务端 `server/` 未改。

## 一句话结论

只要链接目标是**资源文件**（带扩展名、且不是 `.md/.html/.htm`），渲染出的 `<a>` 就会自动带上 `download="<另存名>"` 与 `data-router-ignore`——**点击即下载**，而不是浏览器内联打开。

```html
<a href="./assets/u3报表取数公式说明.pdf" download="U3报表取数公式说明.pdf" data-router-ignore>...</a>
```

## 一、三种写法（均可触发）

| # | 写法 | 所在位置 | 由谁处理 | 说明 |
|---|------|---------|---------|------|
| 1 | `<a href="..." download="..." data-router-ignore>下载</a>` | frontmatter 值 | `note-properties-pro` | **值以 HTML 锚点形式书写会被真正渲染**（社区原版会转义成纯文本）。属性原样保留，`href`/`download`/链接文字三者可各写各的 |
| 2 | `[[assets/x.pdf]]`、`[[assets/x.pdf\|另存名.pdf]]`、`[下载](assets/x.pdf)` | frontmatter 值 | `note-properties-pro` | 语法原本就支持，改动只是**命中附件时自动补属性** |
| 3 | `[[assets/x.pdf]]`、`[下载](assets/x.pdf)` | 正文（Markdown 正文里） | `crawl-links-pro` | 同上，在 `<a>` 生成后追加属性 |

frontmatter 示例：

```yaml
---
附件: "[[assets/u3报表取数公式说明.pdf|U3报表取数公式说明.pdf]]"
附件HTML: '<a href="assets/dcom配置手册.pdf" download="DCOM配置手册1.pdf" data-router-ignore>下载</a>'
---
```

三条路径最终产物形态一致（HTML `<a>` + 两个属性），所以页面上看不出写法差异。

## 二、判定规则

统一实现在 `src/util/attachments.ts`（两个 fork **各存一份、内容同源**，避免跨仓依赖）：

| 规则 | 内容 |
|------|------|
| **默认判定** | 取路径最后一段的扩展名；**有扩展名且不是 `.md` / `.html` / `.htm`** → 视为附件 |
| **白名单判定** | `attachmentExtensions` 非空时改为严格白名单（写 `pdf` 或 `.pdf` 都可以，大小写不敏感） |
| **外链跳过** | `http://` / `https://` 开头的目标不处理（正文侧还额外要求站内链接） |
| **无扩展名跳过** | `[[某个页面]]` 这类页面链接不受影响 |

**另存名（`download` 的值）来源**，由 `downloadNameFrom` 决定：

| 取值 | 行为 |
|------|------|
| `alias`（默认） | 别名 / 链接文字**自带扩展名**时用它的文件名（如 `U3报表取数公式说明.pdf`）；否则**回退目标文件名** |
| `basename` | 一律用目标路径的文件名 |

> `alias` 模式带"扩展名检查"是有意的：别名经常是 UI 文案（`下载`、`点此查看`），直接拿来当文件名会下载出**没有后缀**的文件，反而打不开。

## 三、配置项

两处 YAML 都已登记（默认值即为开启，显式写出便于调整）：

`quartz5/quartz.config.yaml`（`crawl-links-pro`，正文路径）：

```yaml
  - source: ../plugins-local/crawl-links-pro
    enabled: true
    options:
      markdownLinkResolution: shortest
      downloadAttachments: true
      attachmentExtensions: []
      downloadNameFrom: alias
```

`quartz5/quartz.config.yaml`（`note-properties-pro`，frontmatter 路径）：

```yaml
      htmlInProperties: true
      downloadAttachments: true
      attachmentExtensions: []
      downloadNameFrom: alias
```

| 选项 | 默认 | 作用 |
|------|------|------|
| `downloadAttachments` | `true` | 是否给附件链接挂属性。置 `false` 即退回"普通站内链接"行为 |
| `attachmentExtensions` | `[]` | 显式附件扩展名白名单；空 = 宽松判定（带扩展名且非页面） |
| `downloadNameFrom` | `alias` | 另存名来源（`alias` / `basename`） |
| `htmlInProperties` | `true` | **仅 note-properties-pro**：frontmatter 值形如 `<a …>` 时按 HTML 渲染而非转义 |

社区原版 `note-properties` / `crawl-links` 已设为 `enabled: false`，由本地 fork 替代。

## 五、必须知道的限制

1. **`download` 与 `data-router-ignore` 必须成对。** 站内 SPA 路由只认 `data-router-ignore`（或 `target="_blank"`），**不认 `download`**——少了前者会出现"点了没反应 / 白屏"。
2. **frontmatter 里的值要加引号。** YAML 里含 `[` `]` `{` `}` `:` 的值必须用引号包裹，否则解析失败。
3. **HTML 锚点必须写在值的最开头**（前面只允许空白）。判定正则是 `/^\s*<a[\s>]/i`——写成"说明文字 + `<a>`"这种混合内容**不会**被当 HTML 渲染，仍按纯文本处理。
4. **`href` 要用产物里的规范化路径。** `slugifyPath` 会把空格转 `-`、`&` 转 `-and-`、去掉 `? # < > : " | *`，并把**字母转小写**（中文、`()`、`.` 保留）。例如源文件 `assets/DCOM配置手册.pdf` → 链接写 `assets/dcom配置手册.pdf`。
5. **只改渲染属性，不改内容。** 附件仍按原样进产物、进索引；不涉及 `static/` 下的文件、也不涉及图谱 / 目录树行为。
6. **外链、`![[...]]` 内嵌不受影响。** `![[x.pdf]]` 仍是 `<iframe class="pdf">` 页内预览，能下载的是 iframe 里的浏览器控件。
