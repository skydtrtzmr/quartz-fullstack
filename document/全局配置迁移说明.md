# 全局业务配置与 Go 接口

Go Server 的业务读写只面向 YAML 的 configuration，不再查找具体插件。插件清单仍可用于元信息展示，但不用于业务参数定位。

| 业务规则 | 全局位置 | JSON |
| --- | --- | --- |
| 目录聚合字段链 | configuration.aggregation.branches.folders | folder 接口 aggregation.fields |
| 目录属性显示链 | configuration.properties.branches.folders | folder 接口 properties.fields |
| 目录排序 | configuration.listingSort.folders | folder 接口 sort.field / sort.order |
| 最小成组数 | configuration.aggregation.minGroupSize | 域接口 aggregation.min_group_size |
| 目录树四项策略 | configuration.explorer | 域接口 explorer |
| 图谱公共默认、主体目录与主体聚合层数 | configuration.graph | 域接口 graph |

## 图谱结构

configuration.graph.defaults 包含 maxVisibleNodes、expandBatchSize、loadBatchSize、coreMinLinks。
configuration.graph.local / folder / dimension / global 可保存四视图覆盖；global 另外保存 folders、coreAggregationMaxLevels。

Quartz5 加载器负责将这些配置注入 graph-pro 的内部选项，同时注入所有组件条目与 emitter。Go 不知道插件名字。布局、力参数、预计算开关等技术参数继续保留在插件 options。

模板及 settings 中 15 个业务域已完成一次性迁移。迁移时比较四类图谱迁移前后的有效参数，保持既有业务筛选、分页和显示行为。图谱技术版本未统一改写；既有技术版本的视图解析由插件自身处理，不是 Go 兼容旧配置路径。

运行时不接受已迁出业务字段仍放在插件 options，不回退、不自动迁移。scripts/migrate-global-graph.mts 是人工执行的一次性源码迁移工具，不是服务端兼容代码。

## Go 接口

POST 建域、PUT 更新与 GET 回显已支持最小成组数、目录树四项、图谱六项。Go 注册表只包含 configuration 相对路径。JSON 名称保留原有下划线约定，U3 字段编码只是对方建表参考，与我方代码无关。

- 未提交字段保持原值；新建继承模板后应用补丁。
- false、0（仅允许非负数的参数）、空目录列表均能明确保存。
- 非法类型、负数、无效路径、业务字段 null 返回 400，不写入 YAML；非法新建也不创建域目录。
- GET graph.view_overrides 为只读信息，列出 YAML 中已有的视图显式覆盖，避免把公共默认误认为所有视图实际值。单独修改四视图覆盖的接口尚未开放。
- folder JSON 保持不变；fields: [] 和 sort: null 仍用于恢复继承。
- Go 不再读取 includeAll 等插件选项。属性渲染的互斥关系由 Quartz5 校验。
- 修改配置后仍需 reset 全量构建才能更新已有静态站点。

完整字段、默认值、示例及校验见 [配置映射表](U3-GoServer-YAML配置映射表.md)。
