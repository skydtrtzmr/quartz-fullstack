# 图谱与列表待优化项

更新日期：2026-10-14。

本文记录本轮开发、代码审查和页面验证发现的后续事项。已确认的问题、潜在风险和待确认方案分开记录；列入待办不表示已经实施。

## 当前已完成及验证范围

- 聚合节点独立分批展开，底部分类条选择加载对象，各组进度独立。
- 当前 `graph.maxVisibleNodes` 沿用已有配置名，表示每张图的首屏节点预算，默认 500，包含文件、聚合、大区；用户后续主动分批加载可以超过该数量。
- `graph.expandBatchSize` 默认 20；`graph.loadBatchSize` 默认 100。
- 文件夹页 SPA 双向切换后列表隐藏的问题已修复：离页清除绑定，重新进入时初始化；旧异步渲染失效后不能提交。
- 实际验证了无聚合 → 有聚合 → 无聚合，以及切换后的列表“显示更多”（20 → 40 条）。
- 图谱分页回归范围包括无聚合 10,000 节点的首屏截断及继续加载、五组独立进度、收起再展开与跨批连线。列表插件原有 38 项测试及新增 SPA 生命周期回归测试通过。此处不等同于全站所有功能已回归。
- 首屏预算调整后，图谱插件 90 项测试及类型检查通过；实际页面验证了无聚合文件夹首屏 40 → 50 → 60、全局图谱主动加载到 47 个节点（首屏预算 40），对应大区已加载 45/1000、未加载 955，按钮仍可用。

## 优先处理

### 1. 调整整体数量限制的语义：首屏限制 + 主动分批加载

**状态：2026-10-14 用户已确认，现已按首屏预算语义调整实现。**

原问题：无聚合时，首屏占满严格上限后，后续无法在图中查看剩余节点，只能从列表访问。

实现约定：

- 整体数量限制改为首屏预算，避免初次加载时将全部节点送入布局与渲染。
- 无聚合时保留“当前图谱”队列，允许用户主动加载下一批。
- 有聚合时继续通过分类条选择聚合，各组按自己的批次加载；首屏预算不再永久阻止后续加载。
- 继续过滤未显示节点对应的连线，避免出现引用不可见端点的边。
- 明确区分“首屏预算”和“同时可见节点的绝对硬上限”。如果仍需要绝对保护，应单独确定是否增加可选硬上限及其数值，不能把同一参数同时解释为两种含义。
- 为兼容已有 YAML，继续使用 `maxVisibleNodes`，类型注释、界面和 README 明确其首屏含义；本轮不增加同义配置或额外硬上限参数。

验收：无聚合首屏数量受限，点击可逐批增加；五个聚合的进度仍独立；首屏达到预算后按钮仍可用；重复点击、收起再展开、分页之间的连线均正常。

注意：主动分批能防止一次性创建 10,000 个渲染节点；连续加载仍会增加总可见数量，不能据此宣称绝对不会出现性能问题。

### 2. 统一文件夹页、维度值页列表的生命周期

**状态：代码审查确认管理方式不统一，维度值页的同类故障尚未复现。**

- 文件夹列表现已通过 `prenav` 清理绑定；维度值页仍使用可选的 `window.addCleanup` 注册清理。
- 首屏组件脚本可能先于 SPA 安装清理 API 执行，维度值页仍需检查首次进入、离开、返回时的监听器释放。
- 统一进入页面时初始化、离开页面时销毁的约定，并确保重复初始化不会叠加监听器。
- 不为每个新场景继续添加独立的全局标记或补一次初始化调用。

验收：文件夹 → 维度值页 → 另一维度值页 → 文件夹，多次循环后列表数据与当前页面一致，分类变更仅触发当前页面渲染。

### 3. 收敛异步渲染有效性的判断

**状态：维护性优化，当前保护逻辑有效。**

- 外层绑定维护 `latestRender`、`disposed`；列表渲染函数另有私有渲染 token。
- 当前分别保护显示状态和内容提交，但判断分散，后续修改容易遗漏某一层。
- 整理为明确的渲染提交/取消约定，只有有效的当前渲染可以替换内容及显示容器。
- 保留导航取消、快速重排和 DOM 容器复用的保护；不能只删标记追求代码行数减少。

验收：慢请求期间离页、快速切换目录、连续修改分类顺序，旧请求不能覆盖新页面；取消后的回调不能重新显示旧内容。

## 后续体验与性能优化

### 4. 聚合展开后的连线长度和可视范围

**状态：已有用户反馈，布局方案尚未确认。**

- 曾反馈展开后连线偏长、节点分布不理想；此前同心圆布局尝试已按要求撤回。
- 当前继续沿用现有力导向布局。后续应先给出方案并确认，再修改力参数、初始位置或视口适配。
- 观察展开多组后节点超出正文画布的情况；是否需要“适应视图”等入口也需先确认。

验收：单组、多组、加载下一批和收起时，节点位置变化可理解，标签及操作入口可读；不因修改分页控件而擅自改变布局。

### 5. 分类条在窄容器与全屏模式下的空间分配

**状态：适配待完善，尚未完成所有尺寸回归。**

- 全屏画布目前给底部控件预留固定空间，分页条也有最大高度。
- 检查小窗口、侧栏局部图谱、长分类名称、嵌套同名分类及大量分类的换行与滚动。
- 控件与画布空间应协调分配，避免遮挡和没有分页项时的多余留白。

验收：正文、侧栏、全屏及窄屏都能辨认选中分类和完整路径；按钮可操作，画布不被控件覆盖。

### 6. 真实大数据页面的性能回归

**状态：实际页面目前各 1,000 成员；10,000 节点主要由逻辑测试覆盖。**

- 真实页面需补充 10,000 成员场景，分别检查有聚合、无聚合、连续加载后的表现。
- 分开观察数据下载/解析、图数据准备、力导向计算、渲染对象数量以及 SPA 导航后的资源释放。
- 节点进入布局前限量，不代表数据解析和准备阶段的所有开销都已被消除。

验收：记录首屏可交互时间、每批加载耗时及多次导航后的资源表现，再据此确定推荐预算和是否需要绝对上限。
