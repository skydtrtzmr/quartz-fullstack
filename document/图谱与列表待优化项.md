# 图谱与列表待优化项

更新日期：2026-10-21。

## 2026-10-21：四类图谱配置解耦计划与实施

目标是配置解耦、维持当前有效布局及分批行为；不重写力算法，不预计算分类顺序组合。配置 MVP 已实施，后续控制器与加载性能阶段仍待实施。

配置 MVP：`graph-pro/src/options.ts` 统一解析四类视图的有效值，`configVersion: 2` 启用独立的 `localGraph`、`folderGraph`、`dimensionGraph`、`globalGraph`；`graphDefaults` 提供显式公共默认值，视图段优先。文件夹组件不再改写局部配置，维度值页从独立宿主配置读取而非借全局图容器；局部预计算深度在新版统一取 `localGraph.depth`。共享连接数产物仍保存全域事实，筛选门槛在各视图配置生效。未标版本的配置集中走旧规则兼容。

已迁移 `quartz5/quartz.config.yaml`、`settings/graph-demo/quartz.config.yaml`、`settings/wte-20k/quartz.config.yaml`，显式写回原有效的文件夹力参数与维度默认参数；其他业务域仍按旧配置兼容，逐域迁移可参考这三份 YAML。配置解析的旧值与四视图隔离已加回归测试；graph-demo 经 Go server 与浏览器验证四类页面配置及维度画布。控制器职责拆分、数据按需下载与 Pixi 告警不在本次配置 MVP 中。

### 配置契约

- 保留 `localGraph`、`folderGraph`、`globalGraph`，新增 `dimensionGraph`。四者分别描述自身视图，禁止文件夹继承全局力参数、维度值从全局 DOM 读取分页参数等跨视图隐式依赖。
- 新增可选 `graphDefaults`，仅作为明确的公共设置入口（例如拖动、缩放、首屏预算、分批大小）；具体视图显式值优先。默认值、公共值、视图值的归一化在唯一纯函数内完成，不在组件、脚本中分别补值。各视图类型只允许适用字段，禁止全局专用核心/大区参数泄漏到局部图。
- `graph` 最终只保留构建策略。局部邻域目标深度统一用 `localGraph.depth`，构建端按相同值生成；如未来需要缓存更深邻域，再单独定义明确的预计算最大深度，不继续混用 `graph.localDepth` 与显示深度。目录和维度值不使用 BFS depth；全局不使用 depth=-1 充当视图标识。
- 公共实体连接数索引保存事实，主体最少连接数等筛选策略归具体集合视图；不能继续让 selection.json 的单一阈值覆盖所有视图配置。全局构建预筛选与运行时筛选必须使用同一解析结果，避免运行时降低阈值却缺少产物数据。
- 分类字段及目录继承仍以 `configuration.aggregation` 为唯一业务来源，右上角只覆盖已支持字段的当前顺序。四类视图负责如何使用规则，维度值排除已消费字段；不复制四份字段链配置。
- `maxVisibleNodes` 保持“首屏预算”，保留旧键兼容；`expandBatchSize` 与 `loadBatchSize` 保持各自语义，允许每类视图覆盖。不额外增加隐式总硬上限。
- 放大是展示方式，继续使用来源视图配置及数据。当前放大标签 1.25 倍作为兼容显示规则明确保留，不切换为全局图配置。

### 现有结构问题及边界

1. `options.ts` 的 GraphProOptions、Graph.tsx 的 GraphOptions/D3Config、Graph.tsx 默认值、options.ts 全局默认值及 graph.inline.ts 维度默认值分散；`[key: string]: unknown` 掩盖无效配置。统一公开类型、默认值、校验和解析，内部 D3 状态不再充当用户配置协议。
2. FolderGraph 包装 Graph 时改写 localGraph；prepareDimensionContainers 从全局宿主取配置。组件只声明视图与数据地址，所有视图消费同一份规范化配置；共享脚本及配置注入职责不再依附“全局图谱已启用”。
3. graph.inline.ts 同时承担请求、筛选、分组、分页、对象创建、力模拟、弹窗及导航销毁。优先形成视图数据/策略入口、共享图状态、渲染会话三个职责；复用已有 views、expansionPages、expansionControls、graphSimulation，避免四套近似控制器或仅按行数拆文件。
4. 四类视图标识混用 depth、dimensionGraph 和 graphView。最终使用明确的 local/folder/dimension/global，不让 depth 决定数据来源及核心规则。
5. 文件夹与维度值都是集合图，但构建端跨插件。保持各自集合生成职责，明确共同的节点、边、主体集合及协议版本；先通过同一组契约样例验证，不为复用少量代码额外创建共享包。图谱和维度列表的 scope/context/filter 口径须一致。
6. 页内图与放大图继续共用覆盖层外壳，但独立会话持有配置、请求和资源；导航/主题/分类改变的过期结果不可提交。Pixi BindGroup 告警单独定位，不能用配置重构宣称已解决。
7. 注释存在“第一步仅 emitter”“维度调参镜像 local 默认”等过时叙述。随对应职责迁移删除旧路径和陈旧说明，不叠加永久兼容分支。

## 2026-10-21：局部图谱隐藏路径泄漏与配置边界核对

已完成局部图谱聚合状态下的可见性修复，未修改 YAML。配置拆分与文件夹性能待办仍保持下述状态。

用户反馈：`wte-20k/培训课程/course-00032` 的局部图谱出现零散节点；展开“经验案例 → 汽机 → 教学中/评审中”的聚合后，这些节点恢复连线。

已核对该页预计算 JSON（`graph/local/5d/e7/培训课程/course-00032.json`）：深度 2、21 节点、25 边，其中当前课程的直接邻居 5 个，下游节点 15 个。`graph.inline.ts` 的首屏局部分支只排除了聚合成员 ID 及其相连边，其他二度节点仍从全部候选集合进入画布。因此真实关系存在，但当前聚合状态下的可见路径被截断；这不是力布局问题。

修复应统一首屏、分批展开及收起时的可见性约定：

- 当前文件保留；聚合内部的文件尚未实际显示时，依赖它们才能到达当前文件的下游节点也应隐藏。
- 展开到真实文件、且该文件已经进入当前批次后，才按现有深度及批次约定显示可连接的下游上下文，不能因展开一个上层分类就放出整组下游。
- 有其他可见路径的共享节点可以保留；收起后失去全部可见路径的上下文应移除。
- 按当前显示关系从中心判断可达性，不能只删除度数为 0 的节点：一簇节点内部有边也可能整体与中心断开。
- 初始数量预算、后续分批、重复展开和跨分组共享节点均需覆盖；不要改力参数、初始位置规则或伪造边来连接这些节点。

实施与验证：`graph-pro` 在首屏、展开、加载下一批及收起后，按当前可见路径从中心计算上下文可达性；隐藏整簇断开的下游节点，共享节点在仍有路径时保留。新增关联上下文按现有 `loadBatchSize` 限量显示，超出部分复用底部“关联节点”加载入口，聚合成员批次计数不变。保留 `showAggregatedNodeLinks: false` 对原中心连线的抑制。未修改力参数、初始位置算法或其他图谱视图规则。

自动验证：98 项测试通过、类型检查与插件构建通过。Go server 9766 上的上述课程页实测：首屏 9 节点，展开“评审中”后 20 节点，再展开“教学中”后 25 节点，收起“经验案例”回到 9 节点；各阶段与中心断开的节点数均为 0。原始 21 节点包含真实文件及标签，展开后的 25 节点还包含聚合节点。目标业务域已增量构建，触发验证所用的源文件已恢复原始字节。

配置核对：文件夹集合生成逻辑已独立，但配置尚未完整独立。`folderGraph` 当前只支持 `linkDistance`；文件夹的排斥、中心吸引、径向布局参数来自 `globalGraph`，缩放、字体、标签、原中心连线等其他组件参数仍继承 `localGraph`。首屏与分批参数在 `graph` 中共用；`graph.localDepth` 已不控制普通文件夹集合产物，其第一阶段范围固定为目录成员及直接关联。`settings/wte-20k/quartz.config.yaml` 和 `quartz5/quartz.config.yaml` 均已有 `localGraph`、`folderGraph`、`globalGraph`，当前 `folderGraph.linkDistance: 125`、`localGraph.linkDistance: 70`。完整拆分配置应保持现有有效值作为兼容默认值，不能因配置整理改变实际力布局。

文件夹已知待办延续阶段一交付状态：直接关联尚未按需下载，完整重载约 2.9～3.2 秒的首屏问题未解决；Pixi BindGroup 告警仍存在；配置仍耦合；连续主动加载可超过首屏预算，大量可见节点的性能与小画布范围问题仍需后续处理。

- 该产物节点分布：培训课程 3,472（含目录页）、缺陷单 4,794、员工 2,587、经验案例 1,387、设备 1,077、标签 17。边中包含外部节点之间的 13,678 条关系。
- 原因：`graphLocal.ts` 为文件夹补上到全部后代文件的人工出链，并在 `graph.localDepth` 基础上加一层；本域配置为 2，实际 BFS 深度为 3。一次性从全部成员向外扩展，使目录数据膨胀。
- 当次日志显示，从图谱初始化开始到启动绘制约 3.1 秒，缓存返回约 0.63 秒。这是单次诊断记录，不是稳定性能指标；其中约 1.65 秒的前置区间包含请求、其他组件工作和调度等待，不能全部归因于配置请求。23.2 MB 是磁盘体积，不代表启用压缩后的网络传输量。
- 当前代码仍存在文件夹深度加一、图谱在导航时触及共享 `fetchData`、舞台显式销毁后再调用 `app.destroy()` 的路径。`fetchData` 是否在图谱访问前已经被核心启动，需要另行确认，不能仅凭这次访问认定图谱单独触发了下载。
- SPA 切换时出现大量 Pixi BindGroup 纹理/采样器销毁警告，尚未修复。舞台重复销毁、对象池、共享纹理和渲染器绑定的释放顺序均需核对，不能仅删除一处调用就宣称解决。

### 建议的数据边界

| 视图 | 主体集合 | 首次准备的数据 | 展开时准备的数据 |
| --- | --- | --- | --- |
| 文件页局部图谱 | 当前文件 | 当前文件及约定深度的邻域；澄清构建 `graph.localDepth` 与显示 `localGraph.depth` 的关系 | 按交互需要加载或计算关联分组 |
| 文件夹图谱 | 当前目录子树内的真实内容文件 | 成员的必要元数据、成员间真实关系、分组所需字段；首屏展示继续受预算控制 | 被展开主体的直接关联节点与关系 |
| 维度值图谱 | 字段值命中且符合 scope/context/filter 的文件 | 命中主体的必要数据；目录范围与列表一致 | 被展开主体的直接关联；祖先字段不重复聚合 |
| 全局图谱 | 全域按现有主体筛选规则选出的集合 | 主体及首屏分区所需的紧凑数据 | 分区、主体及其关联按交互逐步准备 |

说明：首屏元数据可能仍包含整个主体集合，以支持右上角任意已支持分类字段的切换；这与为所有成员预加载外部邻域不同。若主体间关系本身很密集，也需要关系索引或分块，不能把“仅目录内部”当作绝对体积保证。

### 重点修改及做法

1. **文件夹数据生成独立。** 从 `graphLocal.ts` 移出文件夹特殊遍历，建立明确的文件夹集合生成入口；复用实体筛选、链接索引等底层函数。取消用人工目录中心边驱动 BFS 及 `localDepth + 1`。保留成员间真实链接。目录主体的连接数门槛继续使用全域真实连接数，不能因只加载内部关系而误删主体。根目录、嵌套目录、真实 index 正文及虚拟节点的范围需覆盖。
2. **紧凑数据与真正的按需加载。** 图谱产物只保留 ID、标题、链接/关系索引、分组及配色需要的字段等必要数据，去掉正文和无用元数据。右上角可选字段仍需完整可用，不能只保留构建时默认分类。评估全域共享的主体关联索引及可复用静态分块，避免每个文件夹重复存相同邻居，也避免无节制生成逐节点小文件。不预计算所有分类顺序组合。Go server 继续提供静态文件，是否增加 API 由测量结果决定。
3. **浏览器职责分开。** 视图层负责主体范围、筛选、分组和展开请求；共享层负责节点/边状态、分批进度；渲染层负责 D3/Pixi、交互及销毁。文件夹与维度值可以共用集合展开机制，各自保留集合选择规则；文件局部图保留自己的邻域逻辑。逐步从 `graph.inline.ts` 提取已有职责，避免创建四套近似渲染器或只机械拆文件。
4. **生命周期与异步取消。** 为每张图建立明确的会话生命周期，导航、改分类、主题变化、弹窗关闭时释放旧会话；过期请求、Pixi 初始化和回调不能提交。检查 Pixi 对象、纹理的所有权及正确销毁选项，消除重复销毁。公共分块请求可复用，页面取消不能破坏其他视图共享的有效请求。绑定、缓存和 GPU 资源在多次切页后应稳定。
5. **加载链路与诊断。** 分别记录配置请求、图谱下载、解析、范围筛选、聚合、布局对象创建、Pixi 初始化、首帧与清理耗时；明确原始节点数与实际可见节点数，纠正 `Precomputed JSON rendered` 的误导日志。无依赖的请求并行，域内公共静态数据按构建版本缓存；失败可重试，缓存不无限增长。保留现有目录可交互行为，不恢复已撤回的 priorityStartup 机制。
6. **数量控制保留现有约定。** 继续使用首屏预算、聚合批次和普通批次，以及各组独立的剩余未加载数。连续加载仍可能变大；可讨论同时可见数量提示、主动收起或独立绝对上限，但本次不擅自增加硬限制，也不把 `maxVisibleNodes` 改回永久硬上限。

### 实施顺序与验收

1. 基线诊断及资源销毁修复：同页首次打开、缓存返回、连续切页、快速离页、主题变化与弹窗开关分别记录；警告和残留会话需要实际验证。
2. 文件夹范围与紧凑产物：先用 `graph-demo` 的有聚合/无聚合对照，再用 `wte-20k`；文件夹基础数据不再包含外部文件的多层邻域，成员数、内部真实边、动态分类和分批进度保持正确。
3. 主体关联按需加载：展开主体才读对应关联分块，多主体共享邻居去重；分批、收起再展开、跨批真实连线、原中心连线配置均保持约定。离页或改分类后旧结果不能覆盖当前图。
4. 迁移其余视图并收敛控制器：文件局部图、全局图、维度值图各自验证，再移除旧路径。维度页列表、图谱、计数、预览仍使用一致的筛选语义。
5. 每阶段验证真实增量：新增、改链接、改分类字段、移动、删除、修改聚合配置；更新受影响目录、维度、主体关联分块、manifest 与失效产物。对比同输入下的全量构建结果，忽略时间戳等非语义字段。更新插件 dist 和业务域后才验证浏览器，避免测试旧资源。

数据协议升级需要确定版本、manifest 和旧产物处理方式；首次是否要求 `--reset` 应明确记录。HTML 页面是否按目录静态化是另一项决策，图谱加载改造不依赖先生成所有目录维度页。

### 与其他待办的关系

- 《现存问题》的“节点数量控制”和“聚合节点加载更多”标为基础功能已实现、性能与布局待完善，避免重复开发。
- “验证增量构建”列为正确性验收，不因 2026-10-15 的目录统计专项测试通过而认定全部图谱增量都通过。
- “维度值页 scope 隐藏”当前切换条已隐藏，URL 参数仍负责范围筛选；是否隐藏 URL 或改为目录静态页面需要另外确认，不能直接删参数。
- 后退按钮可独立实现：优先站内历史，直接落地页面提供确定的站内回退目标，避免无历史时按钮无效。
- U3 业务域配置简化单独处理：先梳理旧布局字段的读写与现有配置兼容，再移除旧界面入口，保留必要的业务域配置能力。

待确定的产品语义：文件夹主体是否始终包含全部后代；关联展开默认一跳还是允许继续逐节点展开；连续加载是否需要独立绝对保护；目录静态维度页是否采用。当前建议为全部后代主体、每次展开直接关联，并保留已确认的分页与布局行为。以上建议尚未作为实现变更执行。

## 优先处理

### 1. 调整整体数量限制的语义：首屏限制 + 主动分批加载

**状态：2026-10-14 用户已确认，现已按首屏预算语义调整实现。**

原问题：无聚合时，首屏占满严格上限后，后续无法在图中查看剩余节点，只能从列表访问。

实现约定：

- 整体数量限制改为首屏预算，避免初次加载时将全部节点送入布局与渲染。
- 无聚合时保留“当前图谱”队列，允许用户主动加载下一批。
- 有聚合时继续通过分类条选择聚合，各组按自己的批次加载；首屏预算不再永久阻止后续加载。
- 继续过滤未显示节点对应的连线，避免出现引用不可见端点的边。
- 明确区分“首屏预算”和“同时可见节点的绝对硬上限”。如果仍需要绝对保护，应单独确定是否增加可选硬上限及其数值，不能把同一参数同时解释为两种含义。
- 为兼容已有 YAML，继续使用 `maxVisibleNodes`，类型注释、界面和 README 明确其首屏含义；本轮不增加同义配置或额外硬上限参数。

验收：无聚合首屏数量受限，点击可逐批增加；五个聚合的进度仍独立；首屏达到预算后按钮仍可用；重复点击、收起再展开、分页之间的连线均正常。

注意：主动分批能防止一次性创建 10,000 个渲染节点；连续加载仍会增加总可见数量，不能据此宣称绝对不会出现性能问题。

### 2. 统一文件夹页、维度值页列表的生命周期

**状态：代码审查确认管理方式不统一，维度值页的同类故障尚未复现。**

- 文件夹列表现已通过 `prenav` 清理绑定；维度值页仍使用可选的 `window.addCleanup` 注册清理。
- 首屏组件脚本可能先于 SPA 安装清理 API 执行，维度值页仍需检查首次进入、离开、返回时的监听器释放。
- 统一进入页面时初始化、离开页面时销毁的约定，并确保重复初始化不会叠加监听器。
- 不为每个新场景继续添加独立的全局标记或补一次初始化调用。

验收：文件夹 → 维度值页 → 另一维度值页 → 文件夹，多次循环后列表数据与当前页面一致，分类变更仅触发当前页面渲染。

### 3. 收敛异步渲染有效性的判断

**状态：维护性优化，当前保护逻辑有效。**

- 外层绑定维护 `latestRender`、`disposed`；列表渲染函数另有私有渲染 token。
- 当前分别保护显示状态和内容提交，但判断分散，后续修改容易遗漏某一层。
- 整理为明确的渲染提交/取消约定，只有有效的当前渲染可以替换内容及显示容器。
- 保留导航取消、快速重排和 DOM 容器复用的保护；不能只删标记追求代码行数减少。

验收：慢请求期间离页、快速切换目录、连续修改分类顺序，旧请求不能覆盖新页面；取消后的回调不能重新显示旧内容。
